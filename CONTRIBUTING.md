# Contributing

Start with [AGENTS.md](AGENTS.md). Work through bounded GitHub Issues and short-lived branches. Once the Product Definition and derived architecture establish the outcome, proceed autonomously; do not ask the Product Owner to repeat settled meaning.

Use Node 24 and the committed lockfile:

```text
npm ci
npm run verify
```

Run only the runtime, visual, database, package, or TeX checks whose behavior or evidence premise the change affects. Preserve manual operation without AI, renderer isolation, application-service mutation authority, portable pdfLaTeX documents, and local ownership. Do not add speculative frameworks, broad external access, generic workflow/agent systems, or nonexistent-user compatibility ceremony.

Use `agentic/<short-description>` branches unless the active execution surface requires another convention. PRs state the observable outcome, scope, product trace when applicable, evidence, and real limitations. Use [docs/engineering/EXECUTION.md](docs/engineering/EXECUTION.md) for a bounded cross-surface handoff; do not commit one.
