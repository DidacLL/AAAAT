# Contributing

Start with [AGENTS.md](AGENTS.md). Work through bounded GitHub Issues and short-lived branches. Once the Product Definition and derived architecture establish the outcome, proceed autonomously; do not ask the Product Owner to repeat settled meaning.

Use Node 24 and the committed lockfile:

```text
npm ci
npm run verify
```

Run only the runtime, visual, database, package, or TeX checks whose behavior or evidence premise the change affects. Preserve manual operation without AI, renderer isolation, application-service mutation authority, portable pdfLaTeX documents, and local ownership. Do not add speculative frameworks, broad external access, generic workflow/agent systems, or nonexistent-user compatibility ceremony.

Use `agentic/<short-description>` branches. PRs state the observable outcome, scope, evidence and real limitations. Keep coordination in GitHub rather than committed handoffs, transcripts or duplicate plans.

Current product shaping does not include adding, rewriting, expanding or repairing automated tests without an explicit owner request. Required CI is typecheck/lint. Inspect the real running product for affected behavior and visual quality; passing historical tests cannot establish product acceptance. Run model evaluations only for a concrete evidence question, never as a routine development gate.

The public [README](README.md) and [user guide](docs/USER_GUIDE.md) describe the current desktop experience. [SPEC](docs/SPEC.md), [interaction direction](docs/UX_DEFINITION.md) and [visual direction](docs/UX_VISUAL_DIRECTION.md) explain engineering/product choices. Put active unresolved work in Current Mission and GitHub. Git history preserves discarded development representations.
