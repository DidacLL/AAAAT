# Changelog

## 2.0.0

- Public product website with beginner instructions, independent feature chapters, a clearly labelled fictional interactive preview and platform-specific download guidance.
- A deliberately written 12-opportunity demo spanning community, editorial, visitor services and other work, with consistent fictional career information and reusable documents.

- One application creation screen combines original material and editable information.
- Content-driven sans-serif application covers use configurable prominence and anchored expansion; Tag definitions stay in the left monitor.
- Fixed navigation and contextual top-bar actions keep ordinary work readable.
- Explicit Save/Cancel and navigation-retained drafts prevent accidental persistence or lost edits.
- CVs, cover letters and editable generated-file copies begin provisionally and have contextual names.
- Reusable professional information, custom groups, editable section names, variations and templates remain user-owned.
- Optional AI fills supported empty fields, preserves newer manual edits and offers reviewable new shared Tags.
- Application document permission is checked before configured AI calls; actual context is inspectable on demand.
- Application-linked external requests are fully editable, with exact Copy/Export and explicit future-read permission. Interview requests remain secondary.
- Independent PDF/source projects survive editable-source removal; an application can produce one combined CV-and-letter PDF.
- Native Windows, macOS and Linux installers include optional local llama.cpp/Granite and PDF setup through native installers/software managers.
- Local tools, downloads, pdfLaTeX and the local server's startup script are user-configurable.
- Reset can clear applications, My information or both while preserving generated PDFs and source projects.

AAAAT 2 replaces the earlier prototype with a fresh desktop application. The packaging workflow prepares draft releases; publication follows explicit Product Owner authorization.

## Earlier development

The Python/wx prototype, superseded UX implementations, generated plans and historical transcripts remain recoverable through Git history. They are not active product surfaces or upgrade contracts.
