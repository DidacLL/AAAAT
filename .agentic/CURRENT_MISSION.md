# Current mission — remove v2 configuration and ownership drift

The current Product Owner instruction authorizes cautious corrections to the nearly ready v2 product, without a broad refactor or additional specialists. There is no user-data migration baseline: change the current schema directly and add no compatibility machinery. Preserve the accepted covers, fixed toolbar/rail, Tag monitor, direct field controls, flexible information, provisional documents and disclosure boundaries.

Work is on `agentic/owner-control-corrections`, based on main `79f8050`. [Issue #438](https://github.com/DidacLL/AAAAT/issues/438) tracks native setup and [Issue #428](https://github.com/DidacLL/AAAAT/issues/428) the remaining v2 refinement. Rejected PR #442 remains closed and is not the implementation base.

Reset remains available with Applications, My information, and combined scopes. It clears selected records transactionally, preserves generated PDF/project files and their records, and keeps document content usable after reusable information is cleared. The schema fingerprint compiler and its structural-identity assertions are removed; ordinary SQLite constraints, integrity and workspace identification remain.

AI assistance uses one selected connection, with no synthetic capability certification or operation-routing maps. Capture can stop inference or save manual work while inference is pending; newer manual Tag changes take precedence. Explicit Local AI setup adds its connection without replacing an existing default. Verification must use only the owner's local llama service; no cloud accounts or paid services are authorized.

Optional setup exposes editable tool/download folders and the pdfLaTeX executable. Startup remains fully editable. TeX setup delegates to native installers/software managers, without AAAAT-owned repositories, keys, package updates or mandatory helper dependencies. MiKTeX is a convenient Windows choice, not a requirement; Linux uses native TeX Live. Language labels no longer impose an application allowlist; ordinary TeX/font character support governs rendering.

Keep the existing backup design. The only backup change is correcting Windows cross-drive path comparison. Do not build another backup framework or expand verification into a separate workstream. Identified CSS/source-vocabulary tests and tests of discarded schema/routing behavior are removed without generating replacements.

## Evidence and limits

Local static typecheck/lint and a Windows desktop package build passed during the correction. The packaged settings and location/reset controls were inspected with a separate local profile and an existing disposable, connection-free workspace. No AI calls, test-suite runs, third-party installations or destructive resets were performed. These observations establish the inspected UI and engineering checks, not full product acceptance or fresh cross-platform installation evidence. The final source also passed typecheck/lint and Windows packaging after the form alignment and status wording corrections.

The packaged app also saved and generated a Dutch-language CV with the existing pdfLaTeX installation. Its PDF and compilation output were inspected; this exercises a language outside the removed seven-language allowlist. That journey exposed a false dirty state when choosing a blank CV source: choosing a source is no longer treated as an edited document. The rebuilt package opened a blank CV directly with no discard confirmation. The native Computer helper did not expose the isolated preview's folder dialog, so no reset execution or fresh-workspace UI result is claimed.

No release has been published. The package remains `2.0.0-alpha.0`. Cross-platform native installer handoffs have changed, so the older automated-installation observations cannot certify the new handoffs. Do not turn commercial-provider verification or a new certification programme into a release prerequisite.
